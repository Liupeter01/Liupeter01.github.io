Real-Time Rendering

Vulkan-Platform

A C++17 Vulkan 1.3 renderer with separate graphics, compute and transfer execution paths. I redesigned blocking resource uploads with explicit residency, asynchronous transfer submission and deferred reclamation, using Nsight Graphics to profile the critical path.

Vulkan 1.3 C++17 GLSL / Slang Compute Shaders SPIR-V
  • Reduced worst-case frame time from 424 to 4.66 ms (~91×) through asynchronous resource uploads and deferred reclamation.
  • Steady-state run: 268 FPS at ~700K triangles and 1.1–1.2K draw calls; CPU queue-submission calls measured 0.02–0.1 ms.
  • GPU-resident particle simulation: 16,384 particles, 64 × 256-thread workgroups, ping-pong buffers and explicit compute-to-graphics dependencies.
  • Timeline semaphores, per-frame contexts and completion-gated resource destruction; verified with RenderDoc and Vulkan validation layers.

CPU Rendering · Portable SIMD · Correctness

Software-Rasterizer

A C++17 CPU renderer with 32 × 32 triangle-to-tile binning, scalar and portable SIMDe raster paths, and a BVH-based Monte Carlo path tracer. Tile ownership keeps framebuffer writes local. SIMD accelerates depth interpolation and perspective-correct weights through shared coverage and shading logic.

C++17 SIMDe / AVX2 32 × 32 Tiles BVH Path Tracing
  • Same-machine scalar/SIMDe comparison: median draw time 10.866 → 7.790 ms at 1024 × 1024, a 28.3% reduction (1.395× ratio).
  • SIMDe p95 / p99: 8.487 / 9.406 ms over 3,000 frames; 1080p p50 / p99: 9.069 / 9.886 ms over 1,000 frames.
  • Identical coverage, depth and colour outputs between scalar and SIMD paths in recorded benchmark runs.
  • 21 regression cases covering geometry, visibility, interpolation, scalar/SIMDe agreement, sampling and light transport.
  • Offline path tracing with next-event estimation, cosine-weighted sampling, Russian roulette, and mirror/dielectric scattering.
Workload & timing scope

Recorded 9 October 2026 · Apple M5 Pro · macOS arm64 · AppleClang 21 · Release. Serial task scheduling with TBB disabled; portable SIMDe execution on ARM.

Static Spot mesh · 5,856 input triangles · Phong shading · one point light · 100 warm-up frames per path per run. The 1024² percentiles combine three runs. Pixel coverage: 13.9% at 1024².

Timing scope: draw(), including clear, preparation, binning, depth, interpolation, shading and in-draw allocations. Loading, display, image encoding and file output occur outside the timed region. Metric: draw latency.

CPU / GPU Performance · Concurrent C++

CoreForge

My C++17 performance-engineering library, formerly libHPC. CoreForge combines CPU memory-access optimisation, a CUDA radix-sort pipeline, sparse storage and concurrent-container implementations. Development integrates profiling, numerical validation and concurrency debugging across defined workloads.

C++17 / CUDA SIMD / OpenMP Google Benchmark std::atomic ASan / TSan / UBSan
  • Reordered strided FP32 matrix accesses into 32-column OpenMP blocks: 97.93 → 11.58 ms (8.46×) for 1024 × 1024 matrices.
  • 8192² kernels: 64 × 64 transpose tiling achieved 3.23×; horizontal 17-tap blur with tiling and prefetching achieved 4.55×.
  • Four-pass, 256-bin CUDA radix sort: 500M uint32 keys in 360 ms aggregate kernel time (~1.39B keys/s), using warp primitives and a custom hierarchical scan.
  • 100M-item queue runs: bounded-ring 4P4C median throughput of 4.80M handoffs/s, 2.69× the allocating linked-queue baseline.
  • Combined TSan, ASan/LLDB and happens-before analysis to resolve lost-item and memory reclamation failures, including consumed-state ambiguity, wrong-node release and empty-pop reference rollback.

A C++17 microservice messaging platform built around persistent Boost.Asio TCP connections, gRPC inter-service communication and a custom TLV binary protocol with compile-time type constraints. The TCP connection layer includes dedicated throughput and tail-latency benchmarks.

Boost.Asio gRPC C++17 Redis Docker
